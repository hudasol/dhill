# Route simulation

This is a kinematic and thermal simulation in Python. It is not Gazebo and it is not a physical test. The patrol graph is invented for this exercise. The weather is either synthetic (four scenarios from `src/dhill/weather`) or four real reanalysis days at Abu Dhabi recorded in `tests/data/openmeteo_archive_abu_dhabi_2024.json`. The robot profile is `clearpath_jackal`, which is evidence level L0. The result demonstrates a method. It is not evidence about any real robot.

## Question

Does the envelope change a mission plan, and not only a go or no go answer? A mission is a patrol of depot, T1, T2, T3 and back, with a six minute dwell at each stop and a four hour deadline. Each leg can use the open road (about 5 percent shade) or a sheltered corridor (about 80 percent shade, about 27 percent longer). The planner may also pause at a shaded node.

## Method

Code: `src/dhill/route.py`. Example: `examples/route_demo.py`. Tests: `tests/test_route.py`. No new physics is added. Each piece of a route (drive, wait, dwell) is integrated with the existing engine and its shade input, and the ensemble state is carried from piece to piece.

Policies:

| Policy | What it knows | Decision |
| --- | --- | --- |
| `shortest` | nothing thermal | shortest path, start at the desired time |
| `air_rule` | forecast air temperature | shortest path, start only when forecast air stays at or below 40 C for the whole window, otherwise refuse |
| `envelope_l0` | L0 profile, forecast, parameter uncertainty | depth first search over path variant and pause per leg, fastest feasible first, feasible when every component stays under its limit at the 0.95 risk quantile |
| `envelope_l2` | the same, with the profile calibrated on synthetic telemetry from the hidden robot | same search |

Scoring: plans are made for the L0 profile (or the calibrated profile) and executed by a hidden, hotter robot (`alpha_clean` 0.57, shell to interior conductance 9.0 W/K, shell heat capacity 6500 J/K) over 100 weather draws with forecast error heavier than the engine assumes. A mission completes when it is executed without any hard limit violation. A refusal counts as not completed. The `envelope_l2` calibration uses telemetry generated by the same hidden robot, so it is an inverse crime and shows the effect of reduced uncertainty, not a realistic calibration.

Each case is averaged over seven start hours (06:00 to 18:00 local). The run is deterministic with fixed seeds. Raw per start results: `examples/route_results.csv`. Figure: `docs/img/route_simulation.png` (title marks the data as synthetic and reanalysis).

## Candid reading

1. The envelope never ran into a hard limit violation in any case in which it started (violation 0.00 in every row). That is the property it is designed for.
2. The price is availability. With the L0 profile and its parameter uncertainty, the envelope planner completes fewer missions than the other policies in every hot case, and in several cases than the plain air temperature rule. The envelope completes less often than the best other policy in 6 of the 8 cases (abu_dhabi summer, dubai, sweihan, and the May, September and October days). It ties in al_ain winter and on the April day. The per start list printed by the script, and `examples/route_results.csv`, give every start hour at which another policy completed at least 0.05 more often.
3. The air temperature rule at 40 C is a strong baseline here. In the sweihan heatwave it completes 14 percent of start hours with no violation where the envelope completes none. This is a feature of this graph, this profile and this hidden robot, and should not be generalised.
4. Where the envelope runs in hot cases it changes the plan through route choice and pauses, and the mean mission time is 60 to 71 minutes against 55 minutes for the shortest path. The air rule, which can only wait for a cooler window, shows 71 to 91 minutes in its hot cases.
5. The calibrated variant (`envelope_l2`) is not more available in this run. The hidden robot is hotter than the L0 profile, so calibration moves the model toward the hotter truth and refuses more. The benefit of calibration reported in `docs/results.md` (smaller temperature error and a smaller uncertainty margin) is not reproduced by this table.

## Limits

* Fifteen refusals of the envelope variants (5 for `envelope_l0`, 10 for `envelope_l2`, counted over start hours) are search budget exhaustions (4000 evaluations), not thermal refusals. They count as not completed here. The other refusals (26 and 28) are findings that no path and pause combination was feasible in time.
* The graph, shade fractions, dwell time and deadline are invented. Real shade maps are not used.
* The hidden robot differs from the L0 profile in three parameters only. Other model errors are not tested.
* Reanalysis weather is not a station record. Four days are not a climatology.
* Nothing here is a physical test, and no compliance with any standard is claimed.

## Reproduce

```
python examples/route_demo.py --workers 1
```

Runtime is about 10 to 15 minutes. `py -m pytest tests/test_route.py` runs the unit tests.
